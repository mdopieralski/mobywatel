# City list for Bilet miejski: bundled, not a live API (2026-10-26)

## Decision

The city picker in Podróż → Bilet miejski searches a list of Polish towns that ships with the app. It does not
call a search API.

- **Source:** Wikidata (CC0). Towns are items that are a city (Q515 or a subclass) in Poland, have a TERYT
  SIMC id (P4046), are not dissolved, and lie in one of the 16 current voivodeships. Population comes from
  P1082.
- **Size:** 969 towns on 2026-10-26, about 22 KB of source. GUS counts about 1,000 towns, so a few may be
  missing.
- **Build:** `pnpm --filter @mobywatel/content run build:cities` rewrites
  `packages/content/src/cities-data.ts`. The script refuses to write fewer than 900 towns.
- **Loading:** the PWA imports `@mobywatel/content/cities` lazily, so the list loads only on that screen. The
  service worker precaches it, so it works offline (checked in `e2e/offline.spec.ts`).

## Why not a live API

The user suggested connecting an open-source API, for example Nominatim (OpenStreetMap) or GUS TERYT. A
bundled list is better here:

- **Offline:** the prototype must work offline after the first load (CLAUDE.md). A live search would not.
- **Privacy:** nothing typed leaves the phone. An API would see every keystroke.
- **Reliability during judging:** public APIs have usage limits. Nominatim's policy forbids
  search-as-you-type. A rate limit or an outage while a juror is looking would break the demo.
- **Speed:** search is instant, with no spinner and no debounce.

## Revisit when

Matters need more than town names, for example stops, operators or ticket prices. Those would come from the
operators' open data (GTFS), still bundled or cached for offline use.
