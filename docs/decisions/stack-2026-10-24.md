# Stack for the mObywatel prototype

## Decision

- **Vite + React + TypeScript (strict) PWA** in `apps/pwa`, with `vite-plugin-pwa` (Workbox) for the manifest,
  precache and update prompt.
- **pnpm workspaces + Turborepo** monorepo: `apps/*`, `packages/*` (`core`, `content`, `brand`, `ui`),
  following City Turfer's layout so agents and skills carry over.
- **Vercel** hosting: a static build, plus an optional serverless function for the LLM proxy.
- **Tests:** Vitest + Testing Library, Playwright + `@axe-core/playwright` on phone viewports, and
  `node --test` for repo tools.

## Why

- The entry is judged by opening a link on a phone, with no login. A client-only PWA loads fast, works offline
  after the first visit, can be installed, and needs no backend for the scripted demo.
- We chose Vite over Next.js because server rendering adds nothing to a no-login prototype, and service worker
  and offline setup is simpler in a plain SPA.
- A monorepo keeps the domain (matters, reminders, the assistant engine) in pure TS packages that are
  unit-tested without React, and leaves room for a website or API later.

## Open points

- **TypeScript 7** (the Go port) was installed at the root as the latest release. Confirm that Vite,
  `vite-plugin-pwa`, ESLint and Vitest work with it during scaffolding. Otherwise pin `typescript@5`/`6` in
  the affected workspaces (`scaffold-app` skill).
- Router choice (React Router or TanStack Router) and the i18n library are decided at scaffold time. Pick the
  smallest option that supports Polish ICU plurals.
- **Node**: the machine has 22.15.1. Some current dev tools want ≥ 22.22. Upgrade Node 22 (`.nvmrc` says
  `22`).
- **Product name**: TBD by `product-manager` + `brand-designer`. It must not use the mObywatel marks.
